A full-system diagnostic inspection of the Glyph Mania codebase was conducted across the client application, machine learning inference pipeline, database schema, and server runtimes. 2. Root Cause Analysis: The "Unknown Sigil" Detection Bug

Symptom: Every drawn symbol in the Atelier workshop and Glyph Testing studio reported Unknown effector sigil, Unknown sigil for direction top: North Anchor, or Unknown sigil for form slot topLeft: Top-Left Augmentor.

Root Cause Breakdown

  1. Database UUID vs. Semantic ID Mismatch: Supabase migrated sigils with UUID primary keys (e.g., b27411bd-2c07-42c4-bd7f-b8acdaf26cca for Fire). However, existing glyph drafts, seeded presets, and ML predictions referenced semantic identifiers (eff-fire, aug-position) or labels (Fire). In glyph_solidity.ts, getSigil(id) strictly tested s.id === id. Consequently, lookups using semantic IDs or labels always returned undefined.
  2. Cardinal Direction Anchor Fallback Defect: In glyph_semantic_engine.ts, cardinal directional arrows were recognized and segmented into top, right, bottom, and left slots. When converting to compositions, fallback labels were hardcoded to 'North Anchor', 'East Anchor', 'South Anchor', 'West Anchor'. Because the database sigil is named 'Position', lookup failed and generated Unknown sigil: North Anchor.
  3. Uninitialized Machine Learning Weights: recognizeCropCanvas() aborted with available: false when savedWeights in Zustand was empty. On clean startup, savedWeights is null, causing every slot to yield null labels, which immediately triggered solidity failure.
  4. Empty Initial Store State: When components mounted before the asynchronous Supabase query resolved, useAdminSigilsStore.getState().sigils was empty ([]), causing 100% of sigil lookups to fail.

Remediation Deployed

  • Universal Canonical Sigil Resolver (sigils.ts): Built resolveCanonicalSigil() that resolves UUIDs, semantic IDs (eff-fire), element names (fire), cardinal labels (North Anchor, top → Position Augmentor), and form types.
  • Multi-Tiered Inference Pipeline (glyph_semantic_engine.ts): Cardinal directional slots now automatically resolve to the Position Augmentor. Effector and form slots fallback gracefully to exemplar k-NN or foundational presets when weights are not yet trained.
  • Synchronized Backend Edge Logic (glyph_logic.ts): Upgraded edge function validation to support both UUIDs and semantic aliases.

3. Full Architectural Audit & Deep-Dive

3.1 Backend & Data Architecture

Finding: The "Ghost" Express Backend Server
The project contains an active Express.js server (backend/src/server.ts) listening on port 5000 that reads and writes to local files (backend/data/saves.json, backend/data/settings.json).

Impact Analysis: The entire production frontend uses Supabase (@supabase/supabase-js) for Authentication, Database, Storage, and Edge Functions. The Express server is an abandoned legacy backend that creates port collisions, confuses deployment pipelines, and causes architectural drift.

Recommendation: Formally decommission backend/src/server.ts. Migrate settings persistence to a Supabase user_settings table.

3.2 Code Duplication Across 3 Environments

A critical architectural violation is the exact duplication of the ~600-line isSolid() and analyzeSolidity() rule set across three independent files:

  • frontend/src/lib/glyph_helpers/glyph_solidity.ts (Vite / Browser React)
  • backend/supabase/functions/_shared/glyph_logic.ts (Deno / Supabase Edge)
  • backend/src/lib/glyph_logic.ts (Node.js / Express)

Risk: Any change to game balance, tolerance thresholds, or sigil requirements must be manually applied in 3 places. Any drift causes glyph saves to fail server-side validation.
